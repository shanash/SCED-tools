# Korean coverage metric — the authoritative number, and what it supersedes

**Tool:** `SCED-tools/scripts/build-korean-card-index.py --packs all --coverage`
**Design:** `.am/korean-coverage-metric/design.md` · **Analysis:** `.am/korean-coverage-metric/analyze.md`
**Schema:** `korean_coverage_report.json` `schema_version` `1.0.0`

---

## 1. The superseding statement (scoped)

This report **supersedes** `SCED-downloads/misc/localization_reports/Korean_report.json`
(generated by `SCED-downloads/misc/language-pack-completion-stats.py`) **for one purpose only:
judging whether Korean langpack content actually renders Korean art.**

The superseded metric decides coverage by GMNotes-id set intersection and **never reads an image
URL**. `generate_lang_id_set()` returns a bare `set()` of ids and inspects no other field, so an
object that sits inside a pack advertised as Korean, carries the right id, and still points its
`FaceURL` at the English Steam host scores as *covered* there. This report reads the host of the
image URL each object actually points at, so that object scores `english`.

**It does NOT supersede** `Korean_report.json`'s inventory of ids that are **required but absent**
from the Korean tree (`content[].missing[]`). This script never reads the English base tree and
therefore cannot produce that list. Claiming a broader supersession than the artifact supports
would be an overclaim; the two artifacts answer different questions and both are needed.

## 2. The two numbers, side by side

| metric | headline | what it counts |
|---|---:|---|
| `korean_coverage_report.json` (this tool) | **20.19 % Korean** | objects whose face image URL is on the Korean R2 host, over objects whose host is recognisable at all |
| `Korean_report.json` (incumbent, dated 2026-08-06) | **86.70 %** | ids present under the Korean folder, over ids required by the English base tree |

**The 66-point gap is the feature, not a bug.** The two metrics measure different things: presence
of an id versus language of an image. Measured on this tree, **5,126 objects (4,788 distinct ids)**
carry a parseable id — so the incumbent scores them covered — while their face image is not Korean.
That population is the report's own justification and is emitted as
`disagreement_with_incumbent`, derived entirely from this walk. No incumbent code is ever executed:
`language-pack-completion-stats.py`'s `get_master_map()` unconditionally rewrites a tracked cache
file, and nothing here imports, execs or calls it. `--incumbent-report` is a plain `json.load` of a
data file and nothing more.

## 4. Method

- **Counting unit: the object.** Not the id. Objects are keyed by `(pack, source_file)` and are
  never collapsed by id, so no last-write-wins dict exists anywhere in the rollup.
- **Verdict driver: the FACE image.** For a card that is the selected `CustomDeck` entry's
  `FaceURL`; for a `Custom_PDF` (scenario guides, campaign logs) it is `CustomPDF.PDFUrl`.
  `image_source_field` records which field produced the verdict, so a card verdict and a PDF verdict
  are never conflated.
- **Host map:** `pub-05b4fa32b44341d797f5c66d59384724.r2.dev` → `korean`;
  `steamusercontent-a.akamaihd.net` → `english`; anything else, including an absent or relative URL,
  → `unknown`.
- **`unknown` is declared, never absorbed.** It is reported in `totals.unknown` and broken down by
  host in `unknown_breakdown`, and it is **excluded from the denominator** of `korean_pct`.
  `denominator = korean + english`. This follows koreanize's `objects_without_korean_text`
  precedent: declare the remainder.
- **`korean_pct` is `null` when `denominator == 0`** — never `0.0`. `0.0` would say "measured,
  nothing Korean" where the truth is "nothing was measurable". The CSV writes the empty string there
  and keeps its 15 columns.
- **The back is recorded but never votes.** It is rolled up independently in `back{}` alongside a
  `face_back_mismatch` count, which counts **korean/english crossings only** — the population a
  face-and-back-combined rule would move. An `unknown` on either side is a non-measurement, not a
  disagreement. Emitting the count is what makes the face-driven choice auditable rather than
  assumed.
- **Rollup unit** (`unit_key`, always `<pack>/<unit>`, always `/`):

  | pack | rule | `unit_key_source` |
  |---|---|---|
  | `campaigns`, `fancampaigns` | first path component under the pack root; the file stem for an object sitting directly at the root | `directory` |
  | `playercards` | `cycle-NN` from the two-digit id prefix; `cycle-unknown` when the id is not `^\d{5}` | `id_prefix` |

  Player Cards needs the different rule because the directory rule puts 1,859 of 2,136 objects into
  a single bucket — a rollup with one row is not a rollup. `cycle-NN` is a **derived** taxonomy, not
  a directory and not a name anyone in the project uses; `unit_key_source` is emitted on every row
  so it can never be mistaken for one.
- **Scenario granularity is out of scope, and declared.** Campaign scenario cards sit flat inside
  the campaign directory next to `Scenario.<guid>.json` markers; only 24 of 3,447 campaign files
  nest a further level. Sub-campaign granularity is not recoverable from the decomposed layout, so
  the rollup is not finer than the campaign.

## 5. How to run

```sh
cd SCED-tools

# the authoritative number
/usr/bin/python3 scripts/build-korean-card-index.py --packs all --coverage

# with the read-only side-by-side against the incumbent artifact
/usr/bin/python3 scripts/build-korean-card-index.py --packs all --coverage \
    --incumbent-report ../SCED-downloads/misc/localization_reports/Korean_report.json

# unchanged legacy behaviour: the Player Cards index only, strict invariants
/usr/bin/python3 scripts/build-korean-card-index.py
```

Outputs land in `scripts/output/korean-coverage-metric/` (`--coverage`) or
`scripts/output/korean-player-card-index/` (default). Both are covered by
`SCED-tools/.gitignore:6` (`scripts/output/`), so the artifacts are **untracked and not backed up**
— that is deliberate. The artifact is a ~6 s read-only walk and is cheap to regenerate; the
*statement* is this tracked document.

**Exit 1 is the ordinary outcome of `--packs all --coverage.`** The tree carries anomalies that are
recorded rather than fatal. Do not read it as a failed run, and do not expect any particular anomaly
count — the nightly force-pushes `korean` and koreanize writes into these packs, so the tally moves.

**`--coverage` fuses two effects deliberately** (both stated in its `help=`): tolerant object
resolution *and* report emission. A coverage report that hard-exits on one object out of thousands
is not a coverage report, and tolerant parsing with no report changes the index's anomaly semantics
for no consumer. Without `--coverage` the two hard exits stay hard — the demotion is **mode-scoped**,
so `--packs all` alone still exits 40 on the one `GMNotes_path` object.

## 6. Multi-owner ids: declared, never adjudicated

Ids are physically duplicated inside the Korean tree — the same card file appears under a Challenge
Scenario and under its parent campaign. Measured on this tree: **158 ids appear in more than one
unit, and 48 of those carry conflicting verdicts** (e.g. `02040` is `korean` in
`playercards/cycle-02` and `english` in `campaigns/ReturntoTheDunwichLegacy.ce9130`).

This is empirical proof that the incumbent's `id_to_content_map[card_id] = data` last-write-wins
assignment, fed by a partially-ordered `os.walk`, resolves 48 of these differently depending on
filesystem enumeration order — the same code on the same inputs can differ between machines.

The response here is structural and has three parts:

1. **Never key by id.** Records are keyed `(pack, source_file)`; there is no `dict[id] = record`
   anywhere an id could overwrite.
2. **Count objects, not ids.** A card physically present in two units contributes to both.
3. **Declare, never adjudicate.** `multi_owner_ids.verdict_conflicts` enumerates every conflicting
   id with all its owning units and their verdicts. **This report does not pick a winner.**

**Why attribution is not derivable.** The obvious mechanical disambiguator, `GMNotes.cycle`, does
not hold: `05172`'s cycle reads `"The Circle Undone"` (matching one physical home) while `07064`'s
reads `"Standalone"` despite being duplicated into The Innsmouth Conspiracy. And in Player Cards it
does not exist at all — GMNotes there carries **only** an `id` key across all 2,136 objects, zero
carry `cycle`. Whether a reused card's coverage counts toward the standalone scenario, the parent
campaign, both or neither is a **product decision, not a derivation**. Inventing one would rebuild
the incumbent's nondeterminism with a different mechanism.

two figures look contradictory otherwise.

## 9. Operational notes

- **No CI, and none should be added.** `SCED-tools/` has no `.github/`, and this script is not on
  the nightly path (`daily-sync-local.sh`, `build.py`, `minify.py`, `TTSModManager-Darwin` are).
  Nothing here adds one.
- **Python floor is `/usr/bin/python3` (3.9.6).** The script keeps `from __future__ import
  annotations`, so `X | Y` annotations are strings and never evaluated. Never put a PEP 604 union in
  a runtime position, and no `dataclass`, `typing.get_type_hints`, `match`, or `str.removeprefix`.
- **`--decomposed-root PATH`** relocates the root that `--packs` resolves against. It exists so the
  pytest suite can exercise the multi-pack walk against fixtures at the real pack subpaths; it
  defaults to `SCED-downloads/decomposed` and is ignored by `--source-dir`.
- **`GMNotes_path` sidecars are containment-guarded.** Candidates are `.resolve()`d and refused
  unless they land inside the pack root's parent. `GMNotes_path` is attacker-influenceable data in a
  file the fork syncs from upstream; a refusal prints a stderr line naming the rejected path and
  records `gmnotes_unresolved` — a visible refusal, never a silent skip.
- **Tests:** `SCED-tools/tests/test_build_korean_card_index.py`
  (`python3 -m pytest tests/test_build_korean_card_index.py -q`). The default invocation's
  byte-for-byte compatibility is pinned by `test_default_invocation_output_unchanged`; the
  mode-scoping of the demotion by `test_gmnotes_hard_exit_40_still_fires_without_coverage`.
