그림 1 · 들어가는 것과 나오는 것

81%를 채우고, 나머지 19%는 비운 채로 둡니다

이 기계의 가장 중요한 성질은 “못 한 것을 못 했다고 말한다”는 점입니다. 한국어 그림을 찾지 못한 카드에는 아무 파일도 만들지 않습니다. 그러면 게임은 원래의 영어 카드를 그대로 씁니다.

그림 2 · 작업 순서

여덟 걸음, 그리고 한 번의 관문

모든 단계는 기본이 예행연습입니다. --live를 빼먹으면 아무것도 쓰지 않고 “이렇게 쓸 것”만 보여줍니다. 실수로 써지는 일은 구조적으로 없습니다.

00

--status

읽기만 함

무슨 일이 있어도 이것부터. 아무것도 바꾸지 않고, 지금 상태를 전부 인쇄합니다 — 자물쇠가 잠겼는지, 어디까지 했는지, 밤사이 기준이 움직였는지, 그리고 다음에 칠 명령이 정확히 무엇인지.

SCED-tools/scripts/koreanize/koreanize.sh --status --slug <slug>
지금 결과lock : free · 실행 디렉터리 없음 · 밤사이 기준이 움직였다는 안내. 마지막 줄이 다음 명령을 알려 줍니다.
01

init

쓰지 않음

어떤 시나리오를 할지 정하고 작업 폴더를 엽니다. 끝나면 사람이 읽고 승인해야 하는 문서가 하나 생깁니다. 승인 전에는 다음 단계가 30으로 멈춥니다.

koreanize.sh init --scenario "Challenge Scenario - By the Book"
# gates/init-gate.md 를 열어 범위를 확인하고 status: accepted 로 바꾼다
멈추면30 = 그 문서를 아직 승인하지 않았다는 뜻입니다.
02

source

AI 필요

한국어 그림이 이미 있는 카드를 찾아냅니다. 후보가 둘 이상이면 사람 대신 AI가 골라 줍니다. 226건 중 16건이 여기로 넘어가고, 그중 14건은 판형이 서로 달라 명시적 승인이 필요합니다.

koreanize.sh source --slug challenge-scenario-by-the-book
# 판형이 다른 후보를 받아들이려면:
koreanize.sh source --slug ... --accept-donor-choice
멈추면22 = 판형이 다른 후보가 있다 (위 깃발 추가) · 65 = 열쇠 파일이 없다
03

scaffold

파일을 씀

한국어 꾸러미의 빈 뼈대를 만듭니다. 여기부터가 실제로 쓰는 구간입니다. 먼저 깃발 없이 돌려 예고를 읽고, 그다음 --live로 다시 돌립니다.

# 1) 예행연습 — 기본값이라 깃발이 필요 없다
koreanize.sh scaffold --slug ...

# 2) 진짜 — 배너가 뜨고 LIVE 를 직접 타이핑해야 한다
koreanize.sh scaffold --slug ... --live
멈추면4 = 자물쇠가 잠겼거나 밤 작업 시간대 (아무것도 쓰지 않았음) · 73 = 배너에서 거절함

06

register

파일을 씀

만든 것들을 꾸러미 목록에 정식으로 올립니다. 여기까지 오면 게임이 인식할 수 있는 상태가 됩니다.

되돌리려면koreanize.sh revert --slug ... — 기록해 둔 목록대로 되돌립니다. 되돌릴 게 없으면 13.

결과가 성한지 검사합니다. 대소문자만 다른 파일 이름 충돌처럼 맥에서는 눈에 보이지 않는 문제를 여기서 잡습니다.

koreanize.sh verify --slug ...
멈추면62 = 대소문자만 다른 이름이 겹침 · 67 = 만들어진 결과물이 구조 검사를 통과 못 함
08

git commit

사람이 함

이 단계만은 기계가 대신하지 않습니다. koreanize는 파일을 바꾸는 git 명령을 실행할 수 없게 만들어져 있습니다 — 읽는 명령 네 가지만 허용되고, 나머지는 시도 즉시 거부됩니다. 그래서 커밋은 화면에 인쇄된 명령을 사람이 직접 칩니다.

# koreanize 가 인쇄해 준 명령을 그대로
git -C SCED-downloads add ...
git -C SCED-downloads commit -m "..."
푸시는하지 않습니다. 밤마다 도는 자동화가 배포를 맡습니다.

세 가지 금지

이건 하지 마세요

각각 실제로 사고가 났던 항목입니다. 셋 다 도구가 막아 주지만, 막히는 이유를 알면 덜 당황합니다.

새벽 2–4시에 돌리지 않기

매일 밤 02:02–04:27 KST에 자동화가 같은 작업 공간을 씁니다. 그 시간에 겹치면 4로 거부됩니다.

더 나쁜 경우도 있습니다 — 자물쇠를 koreanize가 먼저 쥐고 있으면, 그날 밤 자동화는 알림도 기록도 없이 조용히 건너뜁니다.

자동화가 쓰는 빌드 도구를 가리키지 않기

KOREANIZE_TTSMM을 자동화의 임시 폴더 안 파일로 지정하면 안 됩니다. 그 폴더는 작업이 끝나면 지워집니다.

맥의 파일 접근 권한이 경로와 지문에 묶여 있어서, 사라지는 경로를 가리키면 권한도 함께 사라집니다.

기준이 움직였다고 되돌리지 않기

--status가 “밤사이 기준이 움직였다”고 하면, 잃은 건 없습니다. 작성 중인 파일은 그대로 있고 기준만 앞으로 간 것입니다.

계획을 다시 세우면 됩니다. revert는 이럴 때 쓰는 게 아닙니다.

지금 할 일

첫 걸음 세 개

순서대로 하면 오늘 안에 첫 시나리오를 끝낼 수 있습니다.

  1. 열쇠 파일 만들기

    이것 하나가 지금 유일한 실질적 장애물입니다. 권한을 0600으로 맞추지 않으면 도구가 거부합니다.

    mkdir -p ~/.config/koreanize
claude setup-token          # 출력된 토큰을 아래 파일에 넣는다
chmod 600 ~/.config/koreanize/env
  2. 상태 확인

    읽기만 하므로 아무 때나 안전합니다. 마지막 줄이 다음에 칠 명령을 정확히 알려 줍니다.

    SCED-tools/scripts/koreanize/koreanize.sh --status
  3. 가장 작은 시나리오로 한 바퀴

    처음에는 --live 없이 끝까지 돌려 보세요. 예행연습만으로도 전체 그림이 보이고, 어디서 멈추는지 미리 알 수 있습니다.

    koreanize.sh init --scenario "Challenge Scenario - By the Book"

이 문서는 오늘 출고본(v0 재사용 리졸버) 기준입니다. 그림을 직접 만드는 v1 체인은 코드가 저장소에 들어왔지만 아이콘 판별 기준이 정해지기 전까지 typeset이 거부하므로 아직 끝까지 돌지 않습니다.
